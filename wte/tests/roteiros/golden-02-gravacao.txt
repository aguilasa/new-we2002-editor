# ESTE CABECALHO CITAVA UMA SEGUNDA ARMADILHA QUE NAO E DESTE EDITOR: o
# `Load`+`Save` trocando os dois primeiros cobradores de cada clube de ML. E do
# `ed.exe`, medida pelo `newWe2002`; aqui "o original" e o `wte.exe`, que grava
# por area. Medido pela CORR-WTE-109 em 2026-08-25: nenhum dos dois caminhos
# que tocam `OFS_KICKER` troca o par ao gravar duas vezes. E este roteiro nem
# grava cobrador -- ele grava barras e nomes.
#
# O roteiro que edita antes de gravar e outro arquivo, e vem depois: e o que
# julga edicao e gravacao juntas (criterio herdado da WTE-TASK-26).
#
# ## A TROCA DE TIME DEPOIS DE CADA GRAVACAO NAO E ENFEITE
#
# O `wte.exe` grava pela saida BUFFERIZADA do runtime C. Clicar o botao **nao**
# produz syscall: os bytes ficam no buffer, e so vao ao arquivo quando algo
# depois procura noutro ponto do mesmo arquivo -- `fseek` esvazia a saida
# pendente antes de mover. Medido nesta task, em tres corridas:
#
#   1. so barras, e o processo morto ao fim   -> ZERO byte no arquivo;
#   2. barras e depois nomes                  -> os 5 bytes das barras aparecem
#                                                na janela dos NOMES;
#   3. barras e depois uma troca de time      -> os 5 bytes aparecem, na janela
#                                                da troca.
#
# Consequencia dupla, e as duas doem:
#
# - **roteiro que termina numa gravacao mede um oraculo truncado.** O harness
#   encerra com `wineserver -k`, e o que estiver no buffer se perde. Se o port
#   gravar direto, o diff acusaria o PORT por bytes que o oraculo nunca chegou
#   a escrever;
# - **a marca de corte tem de vir DEPOIS da descarga**, senao a faixa e
#   creditada a acao seguinte -- foi o que aconteceu na primeira medicao, e os
#   5 bytes das barras apareceram como se fossem dos nomes.
#
# Por isso cada bloco aqui termina com uma troca de time, e so entao a marca.
#
# ## Duas gravacoes, nao seis
#
# Das seis do grupo, so `boton_barras2iso` e `boton_nombres2iso` gravam na
# imagem sem pedir mais nada ao usuario. As outras quatro precisam de dialogo
# de arquivo ou de origem de bytes que ainda nao existe (WTE-TASK-28 e 32), e
# cada uma tera o seu roteiro.
